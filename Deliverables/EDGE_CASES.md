## 2. Edge Case Logging & Solutions

### Edge Case 2.1: No Papers Selected in the UI
When the system presents the discovered papers to the user during the Human-in-the-Loop (HITL) step for selection, there is a risk that the user unchecks all boxes and clicks "Next".

* **Expected Behavior (Target):** The system does not abort the run, but instead displays a clear error message in the UI stating that at least one item must be selected to proceed.
* **Actual Behavior (Actual):** The pipeline passed an empty list into the next agent (Analyst/Synthesizer). Since no data was present, the system crashed in the backend with an error.
* **Chosen Solution:** A validation step was implemented in `app.py` before passing the data to the LangGraph state. If `len(selected_papers) == 0`, the forward progression is blocked and an error message is displayed via `st.error()`. The system no longer crashes and remains available for further requests.

---

### Edge Case 2.2: Invalid / Off-Topic Requests
Entering prompts that have no academic or scientific relevance (e.g., "How do I fix a bicycle?").

* **Expected Behavior (Target):** The `GatekeeperAgent` detects that the query is not an academic research question, blocks the search from starting, and provides feedback.
* **Actual Behavior (Actual):** The gatekeeper was previously implemented as a purely structural dummy (stub) and unconditionally approved every request. As a result, the system attempted to search for irrelevant terms on Semantic Scholar, leading to empty or useless results.
* **Chosen Solution:** The `GatekeeperAgent` was fully implemented. It now utilizes a lean system prompt within the local LLM to classify the request (Scientific: Yes/No). If the model detects a "No", the graph aborts immediately at the very first step, and the UI reflects this with an appropriate message. The system remains stable and can continue to be used.

---

### Edge Case 2.3: No Papers Found / API Request Failed
The Semantic Scholar API returns 0 results, either due to network issues (e.g., HTTP 500 / rate limit reached) or simply because no literature exists on the topic.

* **Expected Behavior (Target):** A clean, user-specific error message explaining why the search cannot proceed, without freezing the Streamlit interface.
* **Actual Behavior (Actual):** The `ScholarTool` threw an unhandled `HTTPError` exception during an API failure. If there were simply 0 matches, the subsequent `IngestorAgent` crashed while attempting to process data that did not exist.
* **Chosen Solution:** The application was safeguarded against this case. Additionally, the `ResearcherAgent` now explicitly verifies the result. If no papers are available, the graph is stopped in a controlled manner, and the UI displays a generic message. This could be further refined in future versions.

---

### Edge Case 2.4: Pressing UI Buttons While the System is Calculating
Since local LLM invocations take a significant amount of time, users tend to get impatient and click buttons (e.g., "Start Search") multiple times.

* **Expected Behavior (Target):** During an active calculation, all interactive elements must be disabled to prevent corrupting the graph state.
* **Actual Behavior (Actual):** The buttons were set to inactive during calculations from the very beginning. Thus, users can only cancel the process or select bullet points and papers for the literature review at the designated steps. Any other interactions that could lead to unintended behavior are restricted.

### Edge Case 2.5: Grammatical Deficiencies with Non-English Requests (German)
The system is fed a research question in German.

* **Expected Behavior (Target):** The system processes the request and generates the final research report in grammatically flawless German.
* **Actual Behavior (Actual):** The final report generated by the `SynthesizerAgent` frequently exhibited sentence structure errors, incorrect articles, or an unnatural mix of English technical terms and German grammar ("Denglisch"). Because the synthesizer's prompts were primarily written in English, the local language model (llama3) drifted linguistically in its output.
* **Chosen Solution:** We have not yet been able to intercept this case. Future versions will need to test whether the faulty text can be proofread and revised by the LLM in a secondary pass.
